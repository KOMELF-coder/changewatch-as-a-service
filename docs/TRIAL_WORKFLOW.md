# Seven-day manual trial

Use one Task and one permanent client ID so a paid continuation can retain its history. Record the trial start/end dates, recipient, three agreed URLs and support contact. Confirm the prospect wants real monitoring emails during the trial.

## Day 0

- Collect three public competitor URLs and names, client email, language and timezone.
- Follow [client onboarding](CLIENT_ONBOARDING.md): threshold 60, daily schedule, automatic confirmation and default 24-hour cooldown.
- Initialize all three baselines and verify no false alert. Resolve any unusable URL with the prospect before declaring it active.
- Manually send the appropriate welcome/activation template, with the actual page count and daily frequency. Record an end-of-trial follow-up date in the operator's existing work process.

## Days 1–7

- Run normal monitoring and send real qualifying alerts. Review health, actual delivery errors and source evidence; fix access issues promptly.
- Do not lower safeguards to manufacture activity. Generic changes may need two observations; explain the ordinary confirmation delay if asked.
- Keep a short evidence log: run dates, successful observations, actual detected changes and delivered alerts. Do not equate an initialized or failed fetch with proof that a page stayed unchanged.

## End of trial

- Share an honest recap: pages covered, successful/failed observations, meaningful detected changes and source links. If no meaningful changes occurred, show the successful run history and explain that no qualifying change was observed. Do not fabricate value or guarantee business impact.
- Offer paid continuation at the agreed scope. With approval, retain the same Task/client ID/snapshots and update the commercial record; no reinitialization is needed.
- Without agreed continuation, stop the trial schedule and follow [offboarding](CLIENT_OFFBOARDING.md). Apply the agreed data policy, not an invented retention period. Do not leave a prospect receiving indefinite trial emails.

Alerts are monitoring signals. A disappearing product is not proof of discontinuation, public pages can become inaccessible, and material decisions should be verified at source.
